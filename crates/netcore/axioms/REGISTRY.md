# What netcore relies on and does not prove

A theorem in this crate says "if the caller and the world are as assumed". This file lists those assumptions. The rule: a fact the kernel relies on and does not prove has a row here and a check, or it is not relied on. For a fact about the world the check is a probe on a real system; for a fact about the caller it is a test of the calling code.

State is one of: **probed** (a probe ran, with what it ran on), **tested** (a test of the calling code checks it, named in the row), **by construction** (no test: the row says what at the call site makes a violation impossible, and a change there would go unnoticed), **unchecked** (nothing checks it yet), **n/a** (the row records that nothing is relied on, so that nobody reads a theorem as saying more).

Ids are stable. An id that no longer names an assumption is listed at the end with what became of it.

## About the world

|---|---|---|---|---|

| NX2 | A reset a box's kernel sends to refuse a connect has the shape `notes` admits: RST with ACK, sequence 0, acknowledging the SYN's sequence plus one, no payload | N1 (a): the refusal of a noted connect is admitted | A probe that connects to a closed port of a box on each target kernel and records the reset | unchecked |
| NX3 | Nothing. The mark on a host-address box's frames is written by the guest's classifier; the theorems hold whoever writes it, and a marked frame gets the cohort's decision | Listed so nobody reads RT1 as "a marked frame is the cohort's" | None needed | n/a |
| NX4 | An address the plan could lease is handed out by one allocator, and is not reused while a table still holds records of its previous holder | G6, N1 and G5 as claims about this box and not a later one at the same address | Test of the calling code: end a box, start another at the same address, and show that no record of the first admits a frame of the second | unchecked |
| NX5 | The switch's DNS server handles at most one question of a payload, answers a payload it cannot unpack with a format error before any handler runs, and sends upstream only a request it builds from that question's name and type, never the bytes a box sent | DQ2 as a claim about what leaves: `zone_query` reads the header and the questions and nothing after them, so a payload malformed after its questions is passed to the resolver | A re-reading of the pinned switch's DNS server and its DNS library at each change of the pin (`pkg/services/dns/dns.go`; the library's `server.go`, `msg.go`, `acceptfunc.go`) | read at the pin (gvisor-tap-vsock v0.9.0, 6dbb5d4f), not probed |

## About the caller

|---|---|---|---|---|
| NC1 | Time is milliseconds from one clock and does not run backwards between calls on one table. Any one unit will do in place of milliseconds: the kernel holds no time constant, and every window, interval and instant is the caller's | Every "unexpired" in G5, G6, G7 and N1. With time running backwards a refresh still never shortens a record, but an expired record can come back to life | Test of the clock source: monotonic, one for each gate | unchecked |
| NC2 | Addresses are `u32` with the first octet most significant, as `frame` produces them, everywhere they enter | Every comparison of an address with the plan | Test with addresses whose four octets differ | unchecked |
| NC3 | The egress entry points are given frames a guest sent, and the ingress entry points frames toward a guest, never the reverse | GE1, GI1: a frame given to the wrong call opens records for the wrong side | Test at the two relay call sites | unchecked |
| NC4 | Two rows have the same `name_id` exactly when they have the same canonical box name | BN1 | Test of the numbering | unchecked |
| NC5 | The alias state (the node's ports, the host's own listeners, the exposures) is the host's actual state | AO1 to AO5 as claims about the host | Test at each place the state changes | unchecked |
| NC6 | The ledger is told of every publish and retraction the host applies, in order, and of nothing it did not apply | L1, and "published" in GI1 | Test of the publish path | unchecked |
| NC7 | The rules, the baseline and the members given to the gate are the compiled rules of the manifest, with "no list" and "an empty list" kept apart | Every decision table as a claim about what a manifest allows | Test that compiles a manifest and compares what the gate is given | unchecked |
| NC9 | When a row is retired the caller retracts every forward that dials its address, before a row is registered there again | GR1 as a claim about the next box: `register` empties the tables, but a forward left in the ledger counts as published for the new row | Test of the retire path | unchecked |

| NC16 | `dns_ask` is called only for a frame the egress decision admitted and the switch's queue took, addressed to the plan's resolver at UDP 53 | GD0 and GD1 (a): a question recorded for a frame that never left opens a table to an answer nothing asked for | Test at the call site | unchecked |
| NC17 | The addresses given to `dns_answer` for a table came from the answer to the named question and passed that table's own filter (its allow and deny lists and the rebinding rules); the two lists at the node's address are filtered separately | G5 and GD1 as claims about names | Test at the call site | unchecked |
| NC18 | A name the table's owner does not declare is never passed as a declared one to `dns_answer`; each distinct undeclared name has its own number, apart from the declared ones | GD1 (d): nothing is admitted for an undeclared name | Test of the numbering | unchecked |

| NC20 | The configuration a frame was routed with is still the gate's when its decision runs: the configuration's read lock is held across both calls | SP1 as a claim about a running system: a row retired and its address registered again in between would get the earlier row's routing | Test: retire an earlier row while a later row's frame is between the two calls | unchecked |
| NC21 | Locks are taken in one order (configuration, ledger, the cohort's DNS tables, the node's tables, the cohort's tables, a row's tables), held until the operation ends, and never two rows' at once | That any concurrent run equals some sequential run of `Gate`, NC24 apart | Test under a lock-order checker | unchecked |
| NC22 | One clock reading for a frame, passed to every call made for that frame. It may be taken before the table's lock; two frames can then reach one table out of time order by the time spent waiting | NC1 on each table. The tables tolerate it as NC1 says | Test of the bound | unchecked |
| NC23 | A frame's source address belongs to its sender: the relay that hands the gate a frame is bound to the address the frame carries | RT1 and everything after it: the gate routes by the source address alone, and no theorem says whose it is | Test at the relay | unchecked |

| NC28 | Each box's tables are built with the limits the caller documents, and where a table has no bound for a key its quota equals its capacity | That a refusal for room happens only at the documented limits | Test of the limits at construction | unchecked |
| NC29 | A box's tables are created, or cleared, before the first frame of a row at that address, and are emptied when the box's rules are replaced | GR1 and NX4 for a caller that holds tables apart from the gate, where nothing in the kernel empties a table for a new row. | NC40 | The `own` addresses given to `answer::answer` are the switch's own, and `box_zone` is false for every answer: a box's DNS tables admit no address in 100.64.0.0/10, and a box's reach to another box is the box-name rule's | TA1 to TA5 as claims about names: the rebinding check reads both | Test at the call site | unchecked |
| NC41 | The bytes given to `dnsa::answer_addresses` are the whole UDP payload of a reply that came from the plan's resolver | DA1 to DA4 as claims about an answer: the reader reads what it is given and does not know where it came from | Test at the call site | unchecked |
| NC42 | A caller of `egress_first` acts on `Arm::RowDns` and `Arm::CohortDns` as drops and asks no judge | EP3: the judges do not know that refusal | Test at the call site | unchecked |
| NC43 | What a judge or the gate is given as a frame is what `egress_first` or `ingress_first` made from the frame's bytes, unaltered | RT2 and every statement about ports, which hold of the facts read from bytes: the frame types have public fields | Test at the call site | unchecked |
| NC44 | The tables handed to a judge are the tables of the box the entry point named | GE1 and IS1 for a caller that holds tables apart from the gate | Test: the tables' owner address is the row's | unchecked |
| NC45 | `published`, given to `finish_ingress`, is true exactly when a forward the host has applied and not retracted dials the frame's destination box at the frame's destination port | FN2 and IG1 as claims about published ports: a record opened for a port nothing publishes admits the box's frames to that client as replies | Test at the call site | unchecked |
| NC36 | `Lifts` are computed for the frame being judged: `box_name` is `Allowed` only when this frame's destination is a registered row the source row names | J1 (b) as a claim about box names: a caller that computes `Lifts` once for a row admits every undeclared destination of that row | Test at the call site | unchecked |

## About the tools

| Id | The kernel relies on | Rests on it | Check | State |
|---|---|---|---|---|
| NT1 | For a function whose contract returns a ghost result (two: `Slab::lower` and `Slab::place`), the body the verifier checks under its generated name is the body an ordinary build compiles under the function's own name. The attribute emits the item twice: the verified one, and a stub under the function's own name marked `external_body` with a false precondition, which no verified code can call | SB1's bound on the entries a search reads, and through `lower` and `place` every lookup and insert of the three record modules | On the pinned verifier: a caller of `place` without `proof_with!` is rejected at the call; with the two ghost results removed in a copy, the crate passes `--no-cheating` | probed on the pinned verifier. ## Not assumptions

- That a guest is honest. Every theorem holds for every frame.
- That a peer follows TCP's close. The theorems hold for every sequence of frames; what a misbehaving peer loses is its own connection.
- That tables are sized well, or that the closed window is long enough for a lost last acknowledgement. The bounds are proved; whether they are large enough is a product question.
- That the record given up at a full table is the right one for the application. The order is proved to be what is done.

# What netcore relies on and does not prove

A theorem in this crate says "if the caller and the world are as assumed". This file lists those assumptions. The rule: a fact the kernel relies on and does not prove has a row here and a check, or it is not relied on. For a fact about the world the check is a probe on a real system; for a fact about the caller it is a test of the calling code.

State is one of: **probed** (a probe ran, with what it ran on), **tested** (a test of the calling code checks it, named in the row), **by construction** (no test: the row says what at the call site makes a violation impossible, and a change there would go unnoticed), **unchecked** (nothing checks it yet), **n/a** (the row records that nothing is relied on, so that nobody reads a theorem as saying more).

Ids are stable. An id that no longer names an assumption is listed at the end with what became of it.

## About the tools

| Id | The kernel relies on | Rests on it | Check | State |
|---|---|---|---|---|
| NT1 | For a function whose contract returns a ghost result (two: `Slab::lower` and `Slab::place`), the body the verifier checks under its generated name is the body an ordinary build compiles under the function's own name. ## Not assumptions

- That a guest is honest. Every theorem holds for every frame.
- That a peer follows TCP's close. The theorems hold for every sequence of frames; what a misbehaving peer loses is its own connection.
- That tables are sized well, or that the closed window is long enough for a lost last acknowledgement. The bounds are proved; whether they are large enough is a product question.
- That the record given up at a full table is the right one for the application. The order is proved to be what is done.
